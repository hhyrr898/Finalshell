## FinalShell 实战：密钥登录与日志查看

对于服务器运维，安全性是第一位的，所以我个人习惯用 SSH 密钥登录，而不是传统的用户名密码。FinalShell 对密钥登录的支持非常好，配置起来也方便。

### 配置 SSH 密钥登录

如果你也想让你的服务器更安全，SSH 密钥登录是强烈推荐的方式。

1.  **生成 SSH 密钥对**：
    如果你还没有 SSH 密钥对，可以打开 Git Bash 或者在 Linux 服务器上执行 `ssh-keygen -t rsa -b 4096` 命令。按照提示一路回车，就可以在 `~/.ssh/` 目录下生成 `id_rsa`（私钥）和 `id_rsa.pub`（公钥）两个文件。私钥要保管好，不能泄露！

2.  **将公钥上传到服务器**：
    将生成的 `id_rsa.pub` 文件内容复制到你的目标 Linux 服务器的 `~/.ssh/authorized_keys` 文件中。
    *   你可以用 FinalShell 的 SFTP 功能，先把公钥文件上传到服务器的某个临时目录。
    *   然后通过 SSH 连接到服务器，执行以下命令：
        ```bash
        mkdir -p ~/.ssh
        chmod 700 ~/.ssh
        cat /path/to/your/id_rsa.pub >> ~/.ssh/authorized_keys
        chmod 600 ~/.ssh/authorized_keys
        ```
    确保 `~/.ssh` 目录权限是 700，`authorized_keys` 文件权限是 600，否则密钥登录会失败。这里有更详细的 [FinalShell SSH 密钥配置教程](/blog/finalshell-ssh-key-configuration/) 可以参考。

3.  **在 FinalShell 中配置会话**：
    打开 FinalShell，点击左上角的“连接”按钮，选择“SSH 连接”。
    *   在弹出的连接配置窗口中，填写服务器 IP、端口号和用户名。
    *   勾选“使用私钥”选项，然后点击右侧的文件夹图标，找到你本地的 `id_rsa` 私钥文件并选择它。
    *   最后，给这个会话起个名字，保存连接。下次你就可以直接双击连接，而不需要输入密码了。

### 实时查看服务器日志

运维时，查看实时日志是排查问题最常用的手段之一。FinalShell 的终端功能 `tail -f` 命令。

1.  **连接到你的服务器**：
    双击你保存的 SSH 会话，连接到你的 Linux 服务器。
2.  **执行 `tail -f` 命令**：
    在打开的终端窗口中，输入类似 `tail -f /var/log/nginx/access.log` 的命令（根据你需要查看的日志文件路径修改）。
    *   回车后，你就可以看到日志内容实时滚动，当有新的访问或事件发生时，会立刻显示出来。
    *   这对于调试 Web 应用、监控系统活动非常有用。

### 快速上传下载文件

FinalShell 的文件传输功能实在是太方便了。

1.  **打开 SFTP 面板**：
    当你连接上服务器后，FinalShell 窗口的左侧通常会显示一个文件浏览器面板，这就是 SFTP 功能区。
2.  **拖拽文件进行传输**：
    *   如果你想上传文件，直接从你的本地电脑文件管理器中，把文件或文件夹拖拽到 FinalShell 的 SFTP 面板中的服务器目录里。
    *   下载也一样，从服务器 SFTP 面板里，把文件拖拽到你的本地电脑文件夹中。
    *   整个过程直观流畅，比命令行 `scp` 命令要友好得多，强烈推荐你看一下这篇 [FinalShell SFTP 文件传输指南](/blog/finalshell-sftp-file-transfer/)。

## 常见问题

在使用 FinalShell 管理服务器时，你可能会遇到一些问题，这里我总结了几个比较常见的：

*   **SSH 密钥登录失败？**
    通常是服务器端 `~/.ssh/` 目录或 `authorized_keys` 文件权限不正确导致的。请确保 `~/.ssh` 目录权限是 `700` (`drwx------`)，`authorized_keys` 文件权限是 `600` (`-rw-------`)。另外，私钥文件格式也可能导致问题，确保是 PEM 格式。
*   **连接服务器总是超时？**
    这可能是服务器防火墙没有开放 SSH 端口（默认为 22），或者 SSH 服务没有运行。你需要检查服务器的安全组规则（如果是云服务器），或者在服务器上检查 SSH 服务状态：`sudo systemctl status ssh`。同时，也检查一下你本地的网络连接是否正常，以及是不是输入了错误的 IP 地址或端口。
*   **SFTP 连接不上，但 SSH 可以？**
    如果 SSH 终端连接正常，但 SFTP 无法连接，这通常意味着服务器上的 SFTP 服务配置有问题，或者某些安全模块（如 SELinux）阻止了 SFTP 访问。有时候可能是 FinalShell 客户端与服务器的 SFTP 协议版本兼容性问题，可以尝试更新 FinalShell 版本。确认服务器上有没有安装 `openssh-server`，它是提供 SFTP 功能的基础。
