## FinalShell 移动端连接，告别频繁掉线！

作为一名喜欢随时随地处理服务器事务的工程师，我常常在手机或平板上用 FinalShell 连接我的服务器。FinalShell 功能强大，但移动端有时连接不稳定，尤其在网络切换或息屏后。SSH 会话容易断掉，每次手动重连都特恼人。最近我把 FinalShell 升级到 **4.5.12** 版本，总结了几个提升移动端连接稳定性的方法，现在再也没那么烦恼了，分享给大家！

![配图说明](/static/images/photo-1486406146926-c627a92ad1ab.jpg)

### 一、开启 SSH KeepAlive 保持会话活跃

SSH 会话断开，多是长时间没有数据传输，服务器误以为客户端掉线。开启 KeepAlive 机制，客户端会定时发送“心跳包”，告诉服务器我还活着，避免被无故断开。

**操作步骤：**

1.  打开 FinalShell，选择服务器连接，右键“属性”进入编辑模式。
2.  在“SSH”选项卡下，勾选“KeepAlive”选项。
3.  我一般将“心跳间隔 (秒)”设置为 `60` 秒。每隔一分钟，FinalShell 就会发送一个小的心跳包。

这个设置能有效减少因空闲导致的连接中断。更多 SSH 配置，请参考我们的 [/blog/finalshell-ssh-key-configuration/](/blog/finalshell-ssh-key-configuration/) 教程。

### 二、调整连接超时与重试参数

网络环境不理想时，FinalShell 自身重连机制也需。调整连接超时和重试次数，可在短暂网络波动后，让 FinalShell 尝试自动恢复连接。

**操作步骤：**

1.  在服务器连接的“属性”窗口中，切换到“基础”选项卡。
2.  将“连接超时 (秒)”设置为 `15` 到 `20` 秒，避免网络短暂卡顿就断线。
3.  “重试次数”设置为 `3` 到 `5` 次，给 FinalShell 几次自动重连机会。

这个小调整，有助于应对移动网络信号不稳的情况。

### 三、利用 FinalShell 的端口转发做“跳板”

有时，移动设备无法直连内网服务器，或直连速度稳定性差。这时，可通过一个公网服务器作为“跳板”，利用 FinalShell 端口转发功能，让移动设备连接到跳板机，再由跳板机转发到目标服务器。

**操作步骤：**

1.  首先，配置一个到“跳板机”的 SSH 连接。
2.  在跳板机连接“属性”中，切换到“端口转发”选项卡。
3.  添加“本地转发”规则：
    *   **监听端口**：例如 `2222`
    *   **远程主机**：目标内网服务器 IP 或域名
    *   **远程端口**：目标内网 SSH 端口（通常 `22`）
4.  保存配置并连接跳板机。你的移动设备即可通过 `localhost:2222` 连接。

通过端口转发，解决访问性问题，还能提升连接质量。详细设置查看我们的 [/blog/finalshell-port-forwarding-guide/](/blog/finalshell-port-forwarding-guide/) 教程。

## 常见问题

### Q1: 设置了 KeepAlive，为什么还会断线？

可能是服务器端 SSH 配置限制了会话空闲时间，需检查 `/etc/ssh/sshd_config` 文件，确保 `ClientAliveInterval` 和 `ClientAliveCountMax` 参数合理。另外，移动网络环境复杂，信号质量、运营商策略都可能影响连接稳定性。

### Q2: 切换 Wi-Fi 或移动网络时，连接会断开吗？

是的，IP 地址变化会导致 SSH 连接中断。FinalShell 无法无缝保持连接，通常需手动重连。KeepAlive 和重试设置能减少在 *同一* 网络环境下，因网络波动或空闲导致的断线。
