FinalShell 4.5.12 是我重装系统后优先安装的工具，它将 SSH 终端与服务器性能监控合二为一，对初次接触 Linux 的用户十分友好。本文将手把手教你完成首次 SSH 连接，解决从新建会话到登录成功可能遇到的困惑。阅读后，你将熟练掌握连接配置，并独立登录到你的第一台远程服务器，整个过程在 Windows 和 macOS 上基本一致。

## 第一步：准备好连接信息

动手之前，请先把三样东西写在记事本上：服务器 IP 地址、SSH 端口（默认是 22）、登录用户名（一般是 root 或你自己创建的账号）。如果你用的是云服务器，控制台里通常能看到公网 IP。密码也要确认好，有些服务商默认给的是密钥登录，需要先搞清楚自己属于哪种方式。

另外确认服务器已经开放 SSH 服务。多数云主机默认开启，本地虚拟机则要自己装 openssh-server，并且防火墙放行 22 端口。

## 第二步：新建一个 SSH 会话

1. 打开 FinalShell，点击左上角的「文件夹」图标，打开连接管理器。
2. 在左侧空白处右键，选择「新建连接」，再选「SSH 连接」。
3. 在弹出的窗口里填写名称（自己看得懂就行，比如「测试机」）、主机填 IP、端口填 22、认证方式选「密码」，再输入用户名和密码。
4. 点「确定」保存，会话就会出现在左侧列表里。

我测试时发现，名称一栏其实可以随便写，但建议带上用途或地区，比如「香港-博客服务器」，机器多了以后找起来快很多。想批量整理会话，可以看 [会话配置备份的做法](/blog/finalshell-backup-session-config/)，避免重装后再一个个手动加。

## 第三步：双击登录并接受主机指纹

回到主界面，双击刚建好的会话。第一次连接时，软件会弹出主机密钥指纹的确认窗口，这是 SSH 的正常流程，核对无误后点「接受并保存」。

接着稍等几秒，终端区域出现 `Last login` 之类的提示，命令行变成 `root@hostname:~#` 这种形式，就说明登录成功了。此时可以在下方状态栏看到 CPU、内存的实时曲线，这也算是 FinalShell 比较直观的一个地方。

如果连接超时或卡住，先别急着改配置，按后文「常见问题」逐条排查。

## 第四步：确认登录状态并试跑命令

登录成功后，我习惯先跑两条命令确认环境：

- `whoami` 看当前用户是否正确；
- `pwd` 看当前目录。

再输入 `ls -l`，如果能正常列出文件，说明终端通道没问题。若中文文件名显示成乱码，多半是编码设置的事，处理方法见我整理的 [中文乱码修复步骤](/blog/finalshell-chinese-encoding-fix/)。上传下载文件则在下方文件面板里拖拽即可，具体操作写在 [SFTP 文件传输教程](/blog/finalshell-sftp-file-transfer-tutorial/) 中。

## 常见问题

### 连接时提示「Connection refused」怎么办？

说明目标端口没有服务在监听。先确认 IP 和端口是否填错，再登录云控制台检查安全组是否放行 22 端口，最后确认服务器上的 sshd 服务是否在运行。

### 密码明明是对的，却提示认证失败？

先检查用户名，很多新手把 root 写成了自己的电脑账户名。其次确认服务器是否禁用了密码登录、只允许密钥认证。复制密码时注意别带上多余空格。

### 登录后过一会儿就断开？

通常是网络空闲超时。可以在会话设置里开启心跳保活，或者调整服务器端的 `ClientAliveInterval`。公司网络或手机热点下这种情况更常见。

### 想换一台电脑继续用，会话能同步吗？

FinalShell 没有官方云端同步功能，会话是存在本地的。换机器需要自己导出配置再导入，所以我养成了定期备份的习惯。

## 写在最后的一点经验

第一次连服务器紧张很正常，我当初还把端口填成了 21。把 IP、端口、用户名、认证方式四件事对齐，登录这一步基本不会卡住。后面熟悉了，再去折腾命令历史、多标签和监控面板，效率会一点点提上来。碰到问题先看报错原文，比反复重装软件有用得多。
