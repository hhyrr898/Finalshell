用 FinalShell 4.5.12 久了会发现，相比 SSH 命令行，左侧的 SFTP 文件面板才是日常操作的核心。这篇文章就专门解决文件上传下载时可能遇到的卡顿与中断问题，让你能熟练处理断点续传，顺利完成传输任务。

本文默认你已经完成了客户端的安装与 SSH 连接配置，可以正常登录服务器。我们将直接进入 SFTP 文件传输的核心操作环节，结合实际界面讲解具体步骤与技巧。

## 一、先认清 SFTP 面板的位置

FinalShell 连上主机后，窗口下半部分或者右侧会有一个文件管理区，左上角显示当前路径，下面分左右两栏：左边是本机目录，右边是远程服务器目录。顶部有一排小图标，分别是上传、下载、新建文件夹、刷新、返回上级。

我第一次用时找了半天「上传」按钮，其实它就在远程路径栏下面，图标是一个向上的箭头。拖动文件到右侧空白区域也能触发上传，两种方式效果一样。

需要注意，SFTP 走的是 SSH 通道，端口默认跟 SSH 一致。如果你的服务器改了 SSH 端口，SFTP 会自动跟着走，不用单独再配。

## 二、上传文件的四步操作

以把一个本地压缩包传到服务器 `/opt/app` 为例：

1. 在右侧远程栏的路径输入框里，手动输入 `/opt/app` 并回车，确认已经进入到目标目录（路径栏会实时刷新）。
2. 在左侧本机栏里逐层点开，找到要传的文件所在文件夹，单击选中那个压缩包。
3. 点击顶部工具栏的上传图标，或者直接把文件从左侧拖到右侧空白处。此时底部会弹出传输队列，显示文件名、大小、速度、进度条。
4. 等待进度条走完，右侧列表会自动刷新出新文件。如果没看到，点一下刷新图标即可。

传多个文件时，按住 Ctrl 多选再一起拖，队列里会逐个排队执行。我测试时发现，同时拖十几个小文件比一个个点上传快不少，但大文件建议一个一个来，免得把带宽占满影响 SSH 命令响应。

## 三、下载文件更简单

下载就是把方向反过来：在右侧选中远程文件，点下载图标，或者拖到左侧目录。

有个细节值得说：下载时 FinalShell 会问你保存到哪，默认是上次用过的目录。如果你经常往同一个本地文件夹拉日志，第一次选好之后后面基本不用改。

### 大文件传输时的界面表现

传输过程中，底部队列会显示实时速率。我传一个 900MB 的镜像时，速度稳定在 3MB/s 左右，进度条偶尔停顿一两秒是正常的，别急着关窗口。这时候如果去敲命令，终端输出可能会有点延迟，属于同一条 SSH 通道被占用。

## 四、传输中断后怎么处理

这是最容易被问到的部分。先说结论：FinalShell 的传输队列在中断后会显示失败状态，它本身没有独立的断点续传开关，续传能力取决于你用的传输方式和文件大小。

实际遇到中断，我一般这么处理：

1. 先看底部队列里那条任务是不是变成了红色失败标记，确认是网络断了还是权限报错。
2. 如果是网络抖动导致中断，直接右键那条任务选择重新传输，或者重新拖一次文件覆盖。小文件覆盖传最省事。
3. 如果是几百 MB 以上的大文件反复断，我会改用命令行 `rsync -P` 或 `scp` 配合 `-C` 压缩，在终端里跑，断了自己重跑，比反复点界面稳。
4. 传输前先确认目标目录有写权限，否则传到一半报 Permission denied，白等。

上周重装系统后我第一次传项目依赖包，中途 Wi-Fi 掉了一次，队列里那条任务卡在 60% 不动。我关掉队列重新拖了一遍，覆盖写入，两分钟就补完了。所以中小文件不用纠结续传，重传反而更快。

### 传输前的两个习惯

一是传之前先看磁盘剩余空间，`df -h` 敲一下不费事；二是压缩包传完记得校验大小，右侧列表里能看到字节数，跟本地对一下。

## 五、几个容易踩的坑

中文文件名乱码是最常见的。传上去文件名变成问号或者方块，多半是编码设置问题，可以参照[中文编码修复的方法](/blog/finalshell-chinese-encoding-fix/)调整一下会话编码再传。

另一个坑是权限。用普通用户登录，往 `/var/www` 这类目录传文件会被拒，要么提前 `chmod`，要么用 root 登录。我习惯先传到家目录，再 `sudo mv` 过去，安全些。

还有人对 SFTP 和 SSH 面板的关系搞不清，以为要单独开一个连接。其实同一个会话里两者共用，切到终端敲命令，切回文件区继续传，互不影响。

如果你还在犹豫用哪个客户端，可以看看[几款工具的实际对比](/blog/finalshell-vs-xshell-vs-tabby-comparison/)，SFTP 这块 FinalShell 的双栏设计确实顺手。

## 常见问题

**Q1：传输到一半卡住不动，进度条一直是同一个数字怎么办？**

先等三十秒，网络瞬断时它会自己重连。超过一分钟没动静，直接取消任务重传。大文件建议换命令行方式，界面队列对这种场景不如终端稳。

**Q2：上传提示 Permission denied，但目录确实是存在的？**

这是目标目录没有写权限，跟路径对不对无关。用 `ls -ld` 看一下目录属主，换有权限的账号，或者先传到有权限的目录再挪过去。

**Q3：能不能后台传，关掉窗口继续下载？**

不行。FinalShell 没有官方的云端同步，也没有独立的后台传输服务，关掉会话传输就断了。要后台跑就用 `nohup` 配合命令行工具。

**Q4：传上去的文件大小跟本地对不上？**

多半是传输中断后被当成了完成，也可能是磁盘满了只写进去一部分。重新传一次并核对字节数，同时 `df -h` 看下空间。

把上面几步走一遍，日常的上传下载基本不会再卡。真正要留意的是权限和编码这两个前置条件，提前处理好，后面点两下就完事。
