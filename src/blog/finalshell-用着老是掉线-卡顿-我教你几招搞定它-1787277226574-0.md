## 常见问题与解决方案

### FinalShell 连服务器老是断线怎么办？

这是很多朋友都会遇到的一个痛点，特别是当服务器闲置一段时间后。其实，很多时候不是服务器或网络的问题，而是 FinalShell 的会话设置在“搞鬼”。

**解决步骤：**

1.  **检查网络稳定性：** 首先，用 `ping` 命令测试一下你的服务器 IP 地址，看看网络是不是抖动严重或者干脆就不通。如果网络本身就不稳定，那 FinalShell 再怎么设置也无济于事。

2.  **配置 SSH KeepAlive (心跳包)：** SSH 连接默认在一段时间没有数据传输后可能会被网络设备或服务器本身切断。FinalShell 的心跳包功能可以有效避免这种情况。
    *   打开你要连接的服务器会话配置 (双击会话或右键 -> `属性`)。
    *   在左侧导航栏选择 `SSH` -> `连接`。
    *   勾选 `发送心跳包`，并将间隔设置为 `30` 秒 (或更短，例如 `15` 秒)。
    *   同时，也勾选 `保持激活`，间隔同样设为 `30` 秒。
    *   点击 `确定` 保存设置并重新连接。这样 FinalShell 就会定期发送小数据包来保持连接活跃。

3.  **调整会话空闲断开时间：** 某些情况下，FinalShell 自己也会因为会话长时间没有操作而自动断开。
    *   在会话配置中，选择左侧导航栏的 `会话`。
    *   找到 `空闲断开` 选项，默认可能是一个较短的时间。你可以将其设置为 `0` (表示永不断开)，或者一个你觉得合理的较长时间，比如 `3600` 秒 (1小时)。

### SSH 密钥一直连不上，FinalShell 提示认证失败是什么鬼？

使用 SSH 密钥登录比密码更安全便捷，但配置不当也容易出现认证失败的问题。FinalShell 4.8.9 版本对 SSH 密钥支持良好，但仍然需要注意细节。

**解决步骤：**

1.  **检查本地密钥文件路径和权限：**
    *   确保你在 FinalShell 会话配置的 `SSH` -> `认证` 中，选择的私钥文件路径是正确的，并且你的私钥文件 (通常是 `.pem` 或 `.ppk` 格式) 没有被移动或删除。
    *   **权限问题：** 在 Windows 上，确保你的私钥文件对当前用户有读取权限。如果是在 Linux 或 macOS 上运行 FinalShell，私钥文件的权限应该是 `600` (只有文件所有者可读写)，否则 SSH 客户端会拒绝使用。你可以通过 `chmod 600 /path/to/your/key.pem` 来设置。

2.  **确认服务器端配置：**
    *   登录到服务器 (如果还能通过密码登录或者其他方式)，检查 `/etc/ssh/sshd_config` 文件。
    *   确保 `PubkeyAuthentication` 选项设置为 `yes`，并且 `AuthorizedKeysFile` 指向的是正确的公钥文件路径 (通常是 `~/.ssh/authorized_keys`)。
    *   你可以通过 `grep -E 'PubkeyAuthentication|AuthorizedKeysFile' /etc/ssh/sshd_config` 来快速查看。
    *   如果修改了 `sshd_config`，记得重启 SSH 服务：`sudo systemctl restart sshd` 或 `sudo service ssh restart`。
    *   查看服务器的认证日志：`tail -f /var/log/auth.log` (Debian/Ubuntu) 或 `tail -f /var/log/secure` (CentOS/RHEL)，这里会有详细的认证失败原因。

3.  **确保密钥格式兼容性：** 虽然 FinalShell 通常兼容多种密钥格式，但有时服务器端对密钥格式有特定要求。如果你是从其他工具导入的密钥，或者密钥是通过旧版工具生成的，可以尝试用 `ssh-keygen` 重新生成一个符合 OpenSSH 标准的密钥对，然后将公钥添加到服务器的 `authorized_keys` 文件中。更多关于 SSH 密钥的配置，可以参考 [FinalShell SSH 密钥配置教程](/blog/finalshell-ssh-key-configuration/)。

### 每次启动 FinalShell 都很慢，有什么办法能提速吗？

FinalShell 功能丰富，但如果配置不当或累积了大量数据，启动速度确实会受影响。我测试时发现，禁用一些非必要功能可以明显改善启动体验。

**解决步骤：**

1.  **关闭启动时自动检查更新：** 每次启动都联网检查更新会耗费时间。
    *   进入 `工具` -> `选项`。
    *   在 `通用` 选项卡下，取消勾选 `启动时自动检查更新`。

2.  **清理历史会话日志：** FinalShell 会记录每个会话的操作日志，长时间使用可能会积累大量数据。
    *   进入 `工具` -> `选项`。
    *   在 `日志` 选项卡下，点击 `清除日志` 按钮，清理掉不再需要的旧日志。
    *   你也可以设置 `保留会话日志天数` 为一个较短的时间，比如 `30` 天，避免日志文件过大。

3.  **关闭不必要的插件或功能：** 如果你安装了第三方插件或者启用了某些不常用的高级功能，可以考虑暂时禁用它们，看看是否能改善启动速度。

### 想给不同的服务器配置不同的代理，FinalShell 能做到吗？

当然可以！FinalShell 允许你为每个独立的会话配置专属的代理设置，这对于需要穿透防火墙或访问特定网络环境下的服务器非常有用。这和 [FinalShell 端口转发指南](/blog/finalshell-port-forwarding-guide/) 中一些网络配置的思路是相通的。

**解决步骤：**

1.  **打开特定会话的配置：** 选中你想要配置代理的服务器会话，右键选择 `属性` (或双击会话名称)。

2.  **找到代理设置：** 在会话配置窗口中，选择左侧导航栏的 `连接` -> `代理`。

3.  **配置代理服务器信息：**
    *   勾选 `启用代理`。
    *   在 `代理类型` 下拉菜单中，选择你的代理类型，常见的有 SOCKS5、HTTP 等。
    *   填写 `代理地址` 和 `代理端口`。
    *   如果代理需要认证，勾选 `需要认证`，并输入 `用户名` 和 `密码`。
    *   点击 `确定` 保存设置。

这样，只有这个特定的会话会通过你配置的代理进行连接，其他会话不受影响。当你需要通过跳板机连接内网服务器时，这个功能尤为实用。

### FinalShell 里的 SFTP 上传下载慢吞吞的，有招吗？

文件传输速度慢是 SFTP 用户经常抱怨的问题。除了网络带宽本身，FinalShell 自身的一些设置也能影响传输效率。关于 SFTP 文件传输的更多细节，可以参考 [FinalShell SFTP 文件传输指南](/blog/finalshell-sftp-file-transfer/)。

**解决步骤：**

1.  **检查网络带宽和服务器负载：** 首先确认你的网络上传/下载带宽是否充足，以及服务器的 CPU、内存和磁盘 I/O 是否在高负载运行。服务器资源不足或网络拥堵是影响传输速度最常见的原因。

2.  **调整 SFTP 传输缓冲区大小：** FinalShell 允许你调整 SFTP 传输时的数据缓冲区大小，适当的调整可能会提高大文件的传输速度。
    *   进入 `工具` -> `选项`。
    *   在 `SFTP` 选项卡下，找到 `缓冲区大小` 选项。
    *   默认值可能是 32KB 或 64KB。你可以尝试将其增加到 `256KB` 或 `512KB`。注意不要设置过大，过大反而可能适得其反，甚至导致传输失败。

3.  **避免传输大量小文件：** 传输大量小文件时，SFTP 的协议开销会显著增加，导致总传输速度下降。如果可能，将小文件打包成一个压缩文件 (如 `.tar.gz`) 再进行传输，会大大提高效率。

## 常见问题

### FinalShell 窗口突然变大或显示异常怎么回事？

这通常是 Windows 系统高 DPI 缩放设置或者显示器分辨率变化导致的。尝试右键点击 FinalShell 的快捷方式，选择 `属性` -> `兼容性` 选项卡，点击 `更改高 DPI 设置`，然后勾选 `替代高 DPI 缩放行为`，并在下拉菜单中选择 `系统` 或 `应用程序`，再重启 FinalShell 试试看。

### 我可以在手机上用 FinalShell 吗？

FinalShell 目前主要针对桌面平台（Windows, macOS, Linux），并没有官方的移动端 App。不过，市面上有很多优秀的移动端 SSH 客户端可以选择，比如 Termius、JuiceSSH (Android)、iTerm (iOS) 等，它们也能提供类似的功能，让你在手机上管理服务器。
