最近不少朋友问我，远程办公或出差时怎么安全便捷地访问公司内网服务，比如开发测试环境或数据库。今天就用 FinalShell 的动态端口转发功能，教你轻松实现内网穿透。我用的 FinalShell 版本是 4.6.1。

![服务器机房一角](/static/images/photo-1547466846-979d34220b30.jpg)

### 什么是 FinalShell 动态端口转发？

简单说，动态端口转发就是在你电脑和远程服务器间建立一条“秘密通道”，让你的本地请求通过远程服务器中转，从而访问远程服务器网络环境中的资源。它提供一个 SOCKS5 代理，让所有需代理的应用都能像在内网一样工作，尤其方便访问多种内网服务。

## 轻松搞定 FinalShell 动态端口转发

下面一步步配置 FinalShell 动态端口转发，非常简单。

### 第一步：打开或新建服务器连接

首先打开 FinalShell。在左侧会话树中找到并双击你的服务器连接。如果没有，需先新建一个 SSH 连接，填写服务器 IP、用户名和密码。连接成功后，点击顶部“隧道”图标，或右键连接会话标签页选择“隧道”。

新手安装可参考：[/blog/finalshell-windows-install-guide/](https://example.com/blog/finalshell-windows-install-guide/)

### 第二步：配置动态端口转发（SOCKS5 代理）

进入“隧道”配置界面。

1.  **选择“动态转发”：** 在左侧选择“动态转发”类型。
2.  **设置本地监听端口：** “本地监听地址”默认 `127.0.0.1`。“本地监听端口”设置一个未被占用的端口，比如 `1080`。这就是你本地 SOCKS5 代理的端口。
3.  **添加并保存：** 点击“添加”，再点击底部“保存”。状态显示“开启”即表示隧道建立成功。

### 第三步：在本地应用中配置代理

隧道建好后，让你的本地应用走这条代理。以浏览器为例（其他应用如 Terminal、IDE 类似）。

1.  **浏览器代理设置：**
    *   Chrome 浏览器建议安装 FoxyProxy 或 SwitchyOmega 插件。
    *   在插件中添加新代理：
        *   **代理类型：** SOCKS5。
        *   **代理服务器：** `127.0.0.1`。
        *   **代理端口：** 你的“本地监听端口”，如 `1080`。
    *   保存并启用该配置。
2.  **验证代理：** 启用代理后，尝试访问内网地址（如公司内部 Web 服务）。如果能正常访问，说明代理成功。你也可以通过 IP 查询网站确认 IP 地址是否为服务器 IP。

FinalShell 的动态端口转发功能强大，可用于开发工具、数据库客户端、命令行工具等，极大地提升了外网访问内网资源的能力。

## 动态端口转发的应用场景

动态端口转发用处很多。我上次出差急需访问公司内网测试环境调试代码，没有 VPN 权限，就是用 FinalShell 搭 SOCKS5 代理解决的。

*   **访问内网 Web 服务：** 公司 Wiki、项目管理系统等。
*   **开发测试：** 远程连接内网数据库、消息队列。
*   **绕过限制：** 某些公共网络限制，SOCKS5 代理可绕过。
*   **私密浏览：** 利用国外服务器进行地区性访问。

合理配置 FinalShell 能大大提升工作效率。

## 常见问题

### 问题 1：启动动态转发时，提示端口被占用？

**解决办法：** “本地监听端口”（如 1080）已被其他程序占用。

*   换个不常用的端口号，如 `1081`、`10086`。
*   命令行查占用（Windows: `netstat -ano`，macOS/Linux: `lsof -i tcp:端口号`），结束进程后重试。

### 问题 2：代理配置成功，但还是无法访问内网资源？

**解决办法：**

*   **FinalShell 连接：** 确保 SSH 连接稳定。
*   **代理设置：** 检查浏览器/应用中 SOCKS5 代理地址和端口是否正确 (`127.0.0.1:端口号`)。
*   **防火墙：** 确认服务器或目标内网服务防火墙未阻止访问。
*   **应用重启：** 有些应用需重启代理才生效，或检查“例外”列表。

### 问题 3：通过代理访问内网资源速度慢，甚至连接中断？

**解决办法：** 多与网络环境有关。

*   **服务器网络：** 检查远程服务器到目标内网资源的带宽和延迟。
*   **本地网络：** 本地到远程服务器的网络质量。
*   **资源负载：** 访问的内网资源本身负载高。
*   尝试更换服务器节点或在网络环境好的时段访问。
